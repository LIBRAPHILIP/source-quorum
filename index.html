Intelligent Contracts · not a product app

Settle a fact from several sources. Not from one model’s opinion.

SourceQuorum is a reusable GenLayer primitive. Validators independently re-fetch a locked source set, extract one structured fact per page, and agree on those facts. Settlement is then computed by deterministic quorum math. The LLM never writes the outcome.

gl.vm.run_nondet_unsafe independent web.get field-level equivalence UNRESOLVED gate challenge as extra source get_settlement consumer API

Purpose

Other builders need an oracle they can point a bond, an insurance trigger, or a market resolver at. Official samples teach the SDK with one URL and a single LLM answer. That is useful. It is not a primitive.

This category

Standalone contracts, readable source, real consensus, tests, and an explanation of how validators agree. No product flow.

Not this

Hello-world storage. Thin exec_prompt wrappers. Format-only validators. Generic “AI decides X” dockets. Full apps belong under Projects.

How consensus is used

Every resolve call is a GenLayer non-deterministic block. The leader proposes a report list. Validators do not grade the leader’s JSON shape. They run the same fetch + extract path and compare decision fields. 

leader_fn:
  for url in locked_sources:
      page = gl.nondet.web.get(url)
      fact = gl.nondet.exec_prompt(extract from THIS page only)

validator_fn(leader_result):
  if not isinstance(leader_result, gl.vm.Return): classify error
  if report URLs ≠ locked set: reject
  mine = leader_fn()                  # independent evidence
  compare fetch_ok, outcome, number
  ignore excerpt, confidence, HTML
  UNRESOLVED vs a concrete outcome → reject (retry)

reports = gl.vm.run_nondet_unsafe(leader_fn, validator_fn)
settlement = compute_quorum(claim, reports)   # deterministic
self.claims[id] = persist(reports, settlement)

Storage writes, contract calls, and transfers happen only after consensus. That is a GenVM rule, and the reason composing contracts read get_settlement instead of re-running an LLM.

The full specification is in docs/CONSENSUS.md.

State machine

DRAFT ──add_source── lock_sources → LOCKED │ resolve() │ ┌───────────┴───────────┐ ▼ ▼ SETTLED UNRESOLVED │ │ └──── challenge() ──────┘ │ CHALLENGED │ resolve() │ SETTLED ── challenge window 24h ── finalize() → FINAL

A challenge adds one new HTTPS URL and spends budget. The next resolve must re-fetch the whole expanded set. FINAL is the immutable consumer snapshot. Details in docs/STATE.md.

Quorum math

The same algorithm lives in the contract (GenVM is self-contained) and in lib/quorum_math.py so it can be unit-tested without Studio.

TypeExtractSettle when
BINARY YES / NO Winner ≥ min_quorum and strictly ahead of second place
ENUM One allow-listed label Same majority rule. Disallowed labels are ignored
NUMERIC A number from the page ≥ min_quorum values inside tolerance_bps of the median. Stored value is that median canonicalized to integer ticks (4 d.p.); validators must match the tick exactly

Ties, insufficient coverage, and numeric dispersion store UNRESOLVED. That is a first-class status. Reviewers can run node --test tests/quorum_math.node.test.js.

Compose with QuorumBond

quorum_bond.py is a consumer, not a second oracle. It never calls an LLM. It reads the primitive through a typed interface and releases bonded GEN. 

@gl.contract_interface
class SourceQuorumIface:
    class View:
        def get_settlement(self, claim_id: str) -> str: ...

oracle = SourceQuorumIface(self.oracle)
settlement = json.loads(oracle.view().get_settlement(claim_id))
# then assign payee; withdraw emits on='finalized'

Parametric

NUMERIC claim over three official pages. Bond pays if consensus numeric_ticks land inside a range.

Public criterion

BINARY claim: rubric page + deliverable page. Bond pays the author on YES.
